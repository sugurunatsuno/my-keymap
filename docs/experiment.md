# 研究ノート / 初期プロトコル

## 問い

- Colemak が使いやすく感じられた理由は、同指連続使用の少なさか、ホームポジションへの近さか、指の移動方向か。
- 記号を中央近くに置かない制約は、日本語ローマ字入力の実測効率にどれだけ影響するか。
- AZIK 的な省略ルールによる打鍵削減は、習得コストや運指負担と引き換えになっていないか。

## 個人の運指についての仮説（2026-11-16時点）

- 本人の所感: 人差し指と中指を主に使っている。
- 現時点では観察にもとづく仮説であり、打鍵頻度や使いやすさが客観的に確認できたわけではない。
- Colemak は指の動きの感触が良かった。Eucalyn は指の動きと中央付近の記号配置に違和感があった。
- 指ごとの移動距離が大きいことは、キーを多く押している証拠にならない。カメラ座標だけで打鍵回数を推定しない。
- 配列探索では、人差し指と中指を優先した仮説モデルと、全指の負担を均すモデルを並行して比較する。薬指と小指を使わないことを前提にしない。

### 検証したい指標

- 左右それぞれの指先移動距離、移動方向、追跡の安定性（まずはカメラで計測）
- 各指の実際の打鍵頻度、同指連続打鍵、キー間遷移（キー位置キャリブレーションや時刻同期の仕組みを用意してから検討）
- 速度、誤打、疲労感や使い心地（別の実験課題/主観記録を組み合わせる）
- 人差し指・中指への集中が効率に寄与しているのか、それとも負担や疲労の偏りになっているのか

## 最初の測定

- カメラは手全体とキーボードが映るよう、固定して上から撮る。セッション間で角度/距離/解像度を変えない。
- 同じ 60 秒の課題文を使う。まずは通常利用の配列で繰り返し記録して、計測の再現性を見る。
- 照明、キーボード、姿勢、入力方式、配列、課題文ID、練習時間、本人の主観メモを別途記録する。
- 生動画は任意。最初は座標のみ保存し、見失いやすい指がないか確認する。

## 初版の指標

| 項目 | 意味 | 注意 |
|---|---|---|
| total_path_px | 指先が画面上で移動した距離 | 撮影条件に強く依存。キー操作回数ではない |
| mean_speed_px_s | 連続検出区間での平均速度 | 移動していない状態も含むサンプル平均 |
| coverage | 全処理フレームのうちその指が検出された割合 | カメラ性能や遮蔽の影響が大きい |
| segments | 座標を結べた隣接フレーム数 | 200ms より大きい途切れは結ばない |

## 次の実装候補

- キーボードの四隅を手動指定し、射影変換でキー単位に座標を合わせる。
- 生のキー入力内容を保存しないイベント収集器を実験モード限定で用意し、時刻同期する。
- キー押下時刻と指先軌跡の対応を推定する。ただし指の重なりやキー判定は確率付きで扱う。
- 日本語コーパスを用意し、ローマ字変換規則を切り替えられる打鍵列ジェネレーターを作る。
- 配列を固定した探索と、記号位置を自由にした探索を同じ評価関数で比較する。

## 比較の原則

QWERTY/Colemak/Eucalyn で現在の習熟度が異なることを記録する。個人の好みと客観的な効率を混同せず、同じ課題、十分な練習、測定順序の入れ替えを検討する。
